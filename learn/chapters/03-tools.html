      Annotations are hints
      
      
      Four optional booleans that describe behavior. Defaults are from the spec (2026-07-28).
      
      
      
      
      
        ⚠️
        
        
          
      • The spec: annotations are not guaranteed. Clients must treat them as untrusted unless the server is trusted.
        • 
          
      • A careful host: annotations can raise the approval level, never lower it. The host's own rules come first.
        •

      tools/list
      
          
        
            
      • Returns the tools available to the caller, in a stable order.
        • 
            
      • May vary by the caller's authorization. Must not vary per connection.
        • 
          
      
        
      
        
      
          
      notifications/tools/list_changed
      
          
        
            
      • Sent by servers that declare listChanged: true, to clients listening via subscriptions/listen.
        • 
            
      • The store server declares false: its 10 tools are fixed at startup.

      What to look for
      
          
        
            
      • The Tools tab lists every tool with its schemas and annotations.
        • 
            
      • Call a read tool, then a write: compare content with structuredContent.
        • 
            
      • Send an ID that doesn't exist: a good server answers with a tool error, not a crash.
        • 
            
      • Send a wrong type: the schema should reject it before any logic runs.
        •

      🎯 Key takeaways
      
        
        
          
      • The name, description and schemas are all the model knows. Make them precise.
        • 
          
      • Return business failures as tool errors (isError) with stable codes so the model can recover.
        • 
          
      • Annotations are hints. The host's approval policy decides what actually runs.

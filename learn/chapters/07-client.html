🕰️ Two protocol eras

          
    
            
  • Modern (2026-07-28): no handshake. Every request carries its version in _meta.
    • 
            
  • server/discover is optional for clients. Servers must implement it.
    • 
            
  • Legacy (2025-11-25 and earlier): an initialize handshake.
    • 
          

        

        

          
🤝 A dual-era client

          
    
            
  • Over HTTP: try a modern request first. Fall back to initialize only on a 4xx without a recognized modern error body.
    • 
            
  • A modern error such as -32022 means "modern server": retry with a supported version instead.
    • 
            
  • Cache the era per server origin.
    • 
          

        

        

          
✅ Capability-driven

          
    
            
  • Only call what the server declared.
    • 
            
  • The store server declares tools, prompts and resources with subscribe: true.
    • 
            
  • Read the server's instructions too, and pass them to the model.
    • 
          

        

      

    


    
    

      💡 Learn
      
The server registry

      
One connection per server, one registry over all of them.


      

        

          
⚙️ From config

          
    
            
  • One entry per server, e.g. { name, url, token }.
    • 
            
  • Short names like store and crm: lowercase, digits, dashes.
    • 
            
  • Reject duplicate names at startup, not at call time.
    • 
          

        

        

          
🧯 One outage is contained

          
    
            
  • Discover every server with Promise.allSettled, not Promise.all.
    • 
            
  • A failing server is reported and skipped. The rest keep working.
    • 
            
  • Only if every server fails, stop with a clear error.
    • 
          

        

        

          
🏷️ One naming rule

          
    
            
  • One server: plain names, search_products.
    • 
            
  • Two or more: every tool becomes <server>__<tool>.
    • 
            
  • __ fits the tool-name pattern many LLM APIs accept, [a-zA-Z0-9_-].
    •

Calling operations safely

      
Retry what's safe to repeat. Classify every failure before reacting.


      

        

          
🔁 Retry after a dropped connection?

          

            
OperationRetryWhy

            
              
*/listYesReads

              
resources/readYesA read

              
prompts/getYesA read

              
completion/completeYesA read

              
tools/callNo*A write may have landed

            
          

          
* Off by default. Opt in only for tools you know are read-only.

        

        

          
⏱️ Timeouts and cancellation

          
    
            
  • Connect: e.g. 10 s per attempt, up to 3 attempts with growing backoff. Never retry auth errors.
    • 
            
  • Request: e.g. 30 s by default, configurable per host.
    • 
            
  • Progress resets the timer, so long scans stay alive. Keep a hard maximum anyway.
    • 
            
  • Cancel: pass an AbortSignal. Ch 06 covers what the server does.
    • 
            
  • Pagination: if a list result has nextCursor, call again with it until it's gone.
    •

▶ Try it for real

        
Use the official MCP Inspector as a client and watch discovery happen. It needs Node 22.19.0 or newer and runs through npx.

        

          
1 · DISCOVER A REFERENCE SERVER
npx @modelcontextprotocol/inspector \
  npx @modelcontextprotocol/server-filesystem ~/Desktop
Look at the server info, its declared capabilities, and which tabs have content.

          
2 · THE SAME, SCRIPTED
npx @modelcontextprotocol/inspector --cli \
  npx @modelcontextprotocol/server-filesystem ~/Desktop \
  --method tools/list
The raw list result. Check for a nextCursor.

          
3 · A REMOTE HTTP SERVER
npx @modelcontextprotocol/inspector \
  --server-url https://store.example.com/mcp \
  --transport http --protocol-era auto
The store URL is illustrative. Use a server you run or can access.

🎯 Key takeaways

        
    
          
  • Discover, don't assume: only call what each server declared.
    • 
          
  • A registry gives the model one catalog, with <server>__<tool> names once several servers connect.
    • 
          
  • Classify every failure. Retry reads, never blindly retry writes, and never retry bad credentials.

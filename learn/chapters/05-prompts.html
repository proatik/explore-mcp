Example ground rules, appended to every prompt

        
    
          
  1. Use only the store data provided in this conversation or returned by tools.
    2. 
          
  2. Do not invent store policies (returns, refunds, shipping times, discounts). If a policy is needed and not provided, say that a team member will confirm it.
    3. 
          
  3. Do not invent customer details, order contents, prices or stock levels.
    4. 
          
  4. Customer emails are masked on purpose. Do not try to reconstruct them.
    5. 
          
  5. Do not change anything in the store unless the user explicitly asks; write operations need human approval.
    6.

▶ Try it for real

        
Use the official MCP Inspector (Node 22.19+) with Everything, the official reference server that ships prompts, resources and tools.

        
    
          
  1. Open the web Inspector and browse the Prompts tab
    npx @modelcontextprotocol/inspector \
  npx -y @modelcontextprotocol/server-everything
    2. 
          
  2. List prompts from the CLI
    npx @modelcontextprotocol/inspector --cli \
  npx -y @modelcontextprotocol/server-everything \
  --method prompts/list
    3. 
          
  3. Get one, then add --prompt-args for its arguments (see the CLI docs)
    … --method prompts/get \
  --prompt-name <a name from the list>
    4. 
          
  4. Point it at your own server
    npx @modelcontextprotocol/inspector --cli \
  https://store.example.com/mcp \
  --transport http --protocol-era auto \
  --method prompts/list
    5.

🎯 Key takeaways

        
    
          
  • Prompts are user-chosen templates; the server writes their content.
    • 
          
  • Ground them: embed the real record and forbid invented policies.
    • 
          
  • Treat user text as data, and check scopes before loading anything.

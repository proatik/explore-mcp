      ♻️ The loop
      
    Eight parts, one loop
    
      
    No agent framework needed: a loop of a few hundred lines. Tap a part.
    

      
    
      
    ↻ Results and refusals go back to the LLM until it answers in text, or the step budget runs out.
    
      
    
      
    The host calls the model itself. Servers never reach the LLM here (Sampling, which let servers ask for completions, is deprecated in 2026-07-28).

    🔌 Swap the model
    
          
      
            
    • Hide the provider behind one interface, e.g. complete(messages, tools, signal)
      • 
            
    • An adapter maps it to the provider's tool-calling API, e.g. tool_choice: 'auto' in OpenAI-style APIs
      • 
            
    • A new provider is one adapter, not a rewrite
      • 
          
    
        
    
        
    
          
    🎭 Test without a model
    
          
      
            
    • A scripted fake model replays fixed steps: call these tools, then say this
      • 
            
    • Steps can read the last tool result, like a real model would
      • 
            
    • End-to-end tests then run the whole loop with no API key

    🎯 Key takeaways
    
        
      
          
    • The host owns the model call: MCP tools become function definitions, results come back as tool messages.
      • 
          
    • Every call ends in a tool message, even errors and refusals, and a step budget stops runaway loops.
      • 
          
    • Keep context lean: structured results, truncation, and history trimmed at a user message.

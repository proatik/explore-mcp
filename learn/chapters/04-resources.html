📚 Resources: the app picks

  • The host or the user decides what goes into context
  • Read-only data, addressed by a URI
  • Typical UI: a picker, a list, an "attach" button

  • Can act and change things (with approval)

Anatomy of a resource

The catalog snapshot from the Lumen & Leaf store server. Tap a field.

resources/list → one entry

Three calls you'll see

Discover, then read. The two list calls support pagination with a cursor.

resources/list
  • Concrete resources the caller can read
  • Returns uri, name, title, mimeType
  • May differ by the caller's scopes
resources/templates/list
  • Parameterized URIs (RFC 6570)
  • Returns uriTemplate instead of uri
  • Arguments can be auto-completed
resources/read
  • Send a uri, get contents
  • Each item has text or base64 blob
  • Unknown URI → JSON-RPC error, never empty contents

Per the 2026-07-28 spec, "not found" is -32602. Clients should also accept -32002 from older versions.

🧩 Templates

Direct resources vs templates

Every URI the example store server offers. Templates reach any product or order without listing them all.

Direct · fixed URI

Scheme: shop://

store/infoany client
store/settingsany client
catalogproducts:read
Template · fill the variable

Scheme: shop://

products/{productId}listed
orders/{orderId}never listed
  • Products can be listed (say, the first 50) so hosts can browse
  • Orders aren't listed, so nobody can browse customer activity. In the TypeScript SDK that's list: undefined

Example capability

          
"resources": { "subscribe": true, "listChanged": false }

          
    
            
  • subscribe: per-resource notifications/resources/updated
    • 
            
  • listChanged: notifications/resources/list_changed when the set of resources changes
    • 
            
  • This server's set is fixed, so it declares listChanged: false
    • 
          

        

        

          
Two protocol eras

          
    
            
  • 2026-07-28: one subscriptions/listen stream with resourceSubscriptions
    • 
            
  • 2025 era: resources/subscribe and resources/unsubscribe per URI
    • 
            
  • A dual-era client checks the era and does either, so it works with both
    • 
            
  • The notification only says what changed. The client re-reads to get the new data

▶ Try it for real

        
Use the official MCP Inspector (Node 22.19+) with Everything, the official reference server that ships resources, templates, prompts and tools.

        

          
1 · OPEN THE INSPECTOR
npx @modelcontextprotocol/inspector \
  npx -y @modelcontextprotocol/server-everything

          
2 · LIST TEMPLATES (CLI)
npx @modelcontextprotocol/inspector --cli \
  npx -y @modelcontextprotocol/server-everything \
  --method resources/templates/list

          
3 · LIST, THEN READ ONE
… --method resources/list
… --method resources/read --uri <a uri from the list>

          
4 · YOUR OWN SERVER
npx @modelcontextprotocol/inspector --cli \
  https://store.example.com/mcp --transport http --protocol-era auto \
  --method resources/list

        

        
Subscriptions need a connection that stays open: watch updates in the web Inspector, not in one-shot CLI runs. Docs: modelcontextprotocol.io/docs/tools/inspector.

🎯 Key takeaways

        
    
          
  • Resources are read-only context addressed by a URI. The app decides what to include.
    • 
          
  • Templates plus completion reach any item without listing everything.
    • 
          
  • Subscriptions keep context fresh: change → resources/updated → re-read.

🎭 Privacy

Send the model less

Whatever a tool returns goes to the LLM provider. Customer 7 from Lumen & Leaf, two ways.

Why it's shaped this way
    Logs get the same care

    Before a log line is written, redact sensitive keys, e.g. authorization, token, secret, password, api_key, email, phone and address become [redacted].

    🚦 Rate limits

    A brake on runaway loops

    A fixed one-minute window per client, keyed by client ID. This demo uses a limit of 5; a real server might allow around 120 per minute (example value).

    Clock0s
    • Over the limit: HTTP 429 with a Retry-After header, before any MCP handling.
    • A fixed window is simple, but allows a burst at the boundary: up to twice the limit across two windows.
    • Cap the agent's steps too (e.g. 8), so a confused model can't loop forever.
    • In-memory counts are per server instance. Behind a load balancer, keep them in a shared store.

    ▶ Try it for real

    Against any MCP server you build, here at http://localhost:3000/mcp. The official MCP Inspector needs Node 22.19+.

    1 · OPEN THE INSPECTOR
    npx @modelcontextprotocol/inspector \
  --server-url http://localhost:3000/mcp \
  --transport http --protocol-era auto
    2 · CHECK THE MASKING (CLI)
    npx @modelcontextprotocol/inspector --cli \
  http://localhost:3000/mcp \
  --transport http --protocol-era auto \
  --header "Authorization: Bearer $TOKEN" \
  --method tools/call --tool-name get_customer \
  --tool-arg customerId=7
    3 · TRY A NARROW TOKEN
    TOKEN=$READ_ONLY_TOKEN   # no customers:read
# rerun step 2: expect a tool error, not data
    4 · TRIP THE RATE LIMIT (bash)
    for i in $(seq 1 10); do
  curl -s -o /dev/null -w "%{http_code}\n" \
    -X POST http://localhost:3000/mcp \
    -H "Authorization: Bearer $TOKEN"
done

    Step 2 should show a display name and a masked email, never a phone or address. Step 3 should fail on the missing scope. Set a low limit (e.g. 3 per minute) before step 4 and watch 429 appear with a Retry-After header. Docs: MCP Inspector · Security best practices.

    🎯 Key takeaways

    • Treat every tool result, resource and description as untrusted data, never as instructions.
    • Layer defenses: the model may be fooled, so approval and scopes must hold anyway.
    • Minimize what the model and the logs ever see: masked, scoped, rate limited.
